# FastRelease

一个 Windows 桌面小工具，把「dev 开发 → cherry-pick 摘取到 release → 推送」这套日常 Git 流程压成几次点击。左右两栏对照分支提交，一键摘取、自动变基拉取、内置冲突解决界面。

## 运行要求

- Windows 10/11（64 位）
- 已安装 [Git for Windows](https://git-scm.com/download/win)，且 `git` 命令在 PATH 里（命令行输入 `git --version` 能出版本号即可）
- 无需安装其它依赖，解压即用

## 启动

双击本目录下的 **`FastRelease.exe`**。

> 注意：exe 必须和本目录里的其它文件（dll、locales 等）放在一起，不能单独拷走。

首次启动是空界面，点「浏览…」选一个 Git 仓库。仓库和分支选择会自动记住，下次打开直接用。

## 界面说明

顶部有两个标签页：

### 快速合并

- **左右两栏**各选一个分支（本地分支和远端分支 `origin/xxx` 都可以选），各自显示提交列表
- 每栏都有：**搜索**（提交信息关键字 / 哈希前缀）、**作者筛选**（下拉，按提交人过滤）、**时间筛选**（今天 / 7 天 / 30 天 / 90 天 / 一年 / 自定义区间）
- 每栏独立的「**拉取**」「**推送**」按钮，推送按钮上会显示领先远端几个提交
- **单击**提交行 = 勾选（可多选、Shift 连选）；**双击** = 查看该提交的完整 diff
- 中间的「**摘取 →**」：把勾选的提交从一侧摘到对侧（自动判断方向），自动切换到目标分支执行 `cherry-pick -x`，保留来源信息
- 「**摘取并推送**」：摘取成功后紧接着推送目标分支，一步到位
- 列表里绿色的「**已摘取**」标记：目标分支上已存在等价补丁（按补丁内容判定，不是按哈希），避免重复摘

### 合并检查

检查「源分支上某些人的提交是否都已经进入了目标分支」：

- 选源分支、目标分支、检测人（默认**全部人**）、时间范围（默认最近 30 天）
- 点「**开始检测**」才执行比对，修改条件不会自动重跑
- 结果里标出每个提交是「已合并」还是「未合并」，未合并的会置顶显示
- 判定用 `git cherry`（补丁内容比对）：cherry-pick 过去、哈希变了的提交也算已合并

## 拉取与变基

「拉取」默认执行 `git pull --rebase`：远端有新提交时，把本地提交重新排到远端之后，保持线性历史。可在设置里切换为仅快进。

推送被拒绝（远端又有新提交）时，工具会询问是否「变基后重新推送」。

## 冲突解决

摘取或变基遇到冲突会打开内置的三栏冲突窗口（类似 TortoiseGitMerge）：

- **左栏** = 当前分支内容（ours），**右栏** = 被摘取的提交 / 你的本地提交（theirs）
- **底部**是合并结果，可直接编辑；冲突块用 `<<<<<<<` 标记
- 「用左侧 / 用右侧 / 两侧都保留」一次解决一处；`Alt+↑/↓` 在冲突之间跳转
- 全部冲突标记清除后「保存并标记已解决」，所有文件处理完点「全部完成，继续」
- 也可以「跳过此提交」或「中止」整体回滚
- 二进制文件冲突单独提示，选一侧即可

## 数据存放位置

- 配置存在 `%APPDATA%\FastRelease\data\config.json`
- 不会往系统其它位置写任何东西，卸载只需删掉本目录和上述配置目录

## 安全约定

- 不提供 force push、不执行 `reset --hard`
- 工作区有未提交改动时，拒绝摘取和变基
- 摘取遇到「补丁已存在」的空提交会自动收尾，不会把仓库卡在半截 cherry-pick 状态
- 所有 Git 操作都会记录在窗口底部的操作日志里，方便排查

## 常见问题

**启动后提示找不到 git / 拉取报错**
确认装了 Git for Windows，并且新开一个命令行窗口输入 `git --version` 有输出。如果 git 装在非标准位置，把它加进 PATH。

**窗口图标是 Electron 默认图标**
exe 文件本身的图标未定制，窗口和任务栏图标是正常的，不影响使用。

**换了电脑 / 删了配置后仓库选择没了**
正常，重新选一次即可。配置只存在本机 `%APPDATA%\FastRelease\data`。

**检测很慢？**
检查默认只比对所选时间范围内的提交，30 天周期的仓库通常几秒内完成。选「全部时间」会比选一个时间段慢，属于正常现象。
