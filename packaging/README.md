# FastRelease 1.1.9

把 dev 上的修复提交，安全地摘到 release（或任意多个分支）上的桌面小工具。

界面参照 TortoiseGit：浅色、紧凑、工具栏 + 列表；冲突解决参照 TortoiseGitMerge 的三栏对照。

## 启动

双击本目录下的 **`FastRelease.exe`**（同目录其它文件是运行时，必须放在一起）。

首次打开选一次仓库，之后会自动记住仓库和分支。

---

## 三个页签

### 快速合并

左右两栏各选一个分支，左边勾提交，点「摘取」或「摘取并推送」，一次过去。
目标分支请选本地分支，不要选远端分支（远端只读）

- 提交上有「已摘取」徽标 = 这个提交在对侧分支已经存在（支持 squash 合并过的场景）
  - **绿色**：补丁完全一致（cherry-pick / rebase 过来的）
  - **蓝色**：补丁虽然不同，但最终文件内容一致（squash 合并的情况）
- 顶部「工作区 N 处改动」可以查看未提交改动的 diff（按行高亮，红色删除 / 绿色新增）

### 合并检查

选源分支、目标分支、检测人、时间范围，看谁还有提交没进 release：

- **已合并**：存在等价补丁
- **已合并(蓝色)**：目标分支文件内容已一致（被 squash 合并过）
- **可能已合并**：同一处被后续改过，判断不了，建议点开看一眼
- **未合并**：确实没有

默认「只看未合并」，上线前核对用这个最省事。

### 代码修复快速合并

同一个修复要发到多个分支时用这个：

1. 左边勾选提交（和快速合并一样）
2. 右边勾选目标分支（可以多选，支持搜索）
3. 点「摘取」/「摘取并推送」

执行时会按顺序一个个分支来：已经包含这些提交的分支会自动跳过，遇到冲突会停下来让你解决，解决完自动继续下一个分支。右栏底部能看到每个分支的结果。

## 几个必须知道的行为

- **会自动切分支**：摘取时会把仓库切到目标分支
- **工作区改动会自动暂存再恢复**：摘取前 `git stash push -u`（含未跟踪文件），完成后自动恢复，连「哪些是已暂存」都保持原样；如果恢复时冲突，会弹冲突界面让你解决，改动不会丢
- **冲突不会卡死**：冲突窗口可以逐块选「用左侧 / 用右侧 / 两侧都保留」；想反悔就点「中止并回滚」
- **推送被拒会自动处理**：远端有别人的新提交时，会先变基再重推一次，不用你再点一遍
- **批量页只列本地分支**：因为摘取需要切到本地分支；左边的源分支可以选 `origin/dev`


## 环境要求

- Windows 64 位
- Git for Windows（`git` 需要在 PATH 里，建议 2.40 以上；老版本会少一层「已合并」判定）

## 常见问题

**双击没反应 / 提示找不到 git？**
确认 `git` 已安装且在 PATH 里（命令行执行 `git --version` 能出版本号）。

**误操作了想回滚？**
冲突窗口里点「中止并回滚」；如果已经摘取完成，用 Git 自己回退（工具不做历史改写）。

**程序报错了想反馈？**
把 `%APPDATA%\FastRelease\data\renderer-error.log` 一起发出来，其中包含异常堆栈。

**配置存在哪？**
`%APPDATA%\FastRelease\data\config.json`（记住的仓库列表、上次分支、页面大小等）。
